**Models to Search:**

| Model | Searchable Fields |
|-------|-------------------|
| Series | title, description |
| Season | (via Series, display as "Series - Season N") |
| Episode | number, title, description |
| Sequence | number, title, description |
| Shot | number, script (content), background, camera_angle, camera_movement, notes |
| Character | name, description |
| Prop | name, description |
| WardrobeItem | name, description |

**Existing Patterns:**
- Views use function-based or class-based patterns
- URLs defined in series/urls.py with app_name="series"
- Templates extend base.html
- Tailwind-like CSS via custom properties in base.html
- Navigation in base.html header with user menu and theme toggle

**Result Structure:**
Each result should include:
- `type`: Model name (e.g., "Series", "Episode", "Character")
- `title`: Display name/title
- `description`: Brief excerpt (optional)
- `url`: Link to detail page using `{% url %}`
- `relevance`: Numeric score for sorting (higher = more relevant)

**URL Patterns for Links:**
- Series: `series:series_detail` (pk)
- Season: `series:season_detail` (pk)
- Episode: `series:episode_detail` (pk)
- Sequence: `series:sequence_detail` (pk)
- Shot: `series:shot_detail` (pk)
- Character: `series:character_detail` (pk)
- Prop: Django admin (no user-facing detail view exists)
- WardrobeItem: Character detail page with anchor

**Search Strategy:**
Use Django's Q objects with `icontains` for case-insensitive partial matching:
```python
from django.db.models import Q
Series.objects.filter(
    Q(title__icontains=query) | Q(description__icontains=query)
)
```

Rank results by: exact match in title/name field (score 100) > partial match in title/name (score 50) > match in description (score 10).
</context>
